# 前端头像与企业名称核对

日常工具：`drawing_read_frontend_account`，读取账号与工作区状态，与扩展弹窗/侧栏共享缓存和在途检测。普通设计端不需要进入施工图才能读取账号。默认每个文档自动检测一次，失败和超时不循环重试；需要明确更新时传 refresh=true，重复在途请求合并。返回 cached/stale 和读取时间，历史结果不能当作刚核对的账号。新版工作线程首次部署需重新加载实际扩展一次。

诊断工具：`drawing_read_frontend_identity`，保留下面的 inspect/hover 两阶段入口。两者都只读取指定设计页右上角头像的 title、悬停提示或实际账号菜单名称，不点击菜单、不切换账号、不读取 Cookie/令牌，不修改、保存或发布配置；都不是完整图纸校验服务。

读取前端账号时，不要求先进入“图纸&清单”。workspace.stage 分别为 design、drawing-editor、drawing-layout；drawingOpen 仅表示当前显示施工图工作区。模板、配置更新、实际效果分别核验，不能由账号名称和账号 ID 自动推断。客户端需要开始效果验收或怀疑换号时明确更新账号；日常刷新和获得焦点不触发重复悬停。

## 定位

1. 调用 `drawing_get_context`。每个浏览器会话返回 `browser`（扩展上报的 Chrome/Edge）；不要按数组顺序、网页域名或“未命名”标题猜浏览器。
2. 代配基础配置时，后端目标取“来自于”名称，不取操作员名称。企业自配置时按当前企业账号核对。不同账号前后端须使用独立会话。
3. 在目标浏览器中选择 `role:design` 的 pageId。单一浏览器的其它设计标签不能替代另一个客户浏览器的设计页。

## 两阶段读取

先检查实际页面元素（示例使用占位值）：

```json
{
  "pageId": "<目标设计页 pageId>",
  "action": "inspect",
  "expectedBrowser": "Edge",
  "expectedCompanyName": "示例企业"
}
```

结果按 `frames` 返回页面和可访问 iframe 的诊断。仅返回页首右侧可见头像/图片候选，accountAvatar 标记来自头像元素或祖先的实际 avatar/头像属性，不再只接受某个施工图工具栏类名；普通装饰图标不能作为账号入口。选择真实头像所在帧及其 avatarKey，不能任意取第一张图片。隐藏、透明或在视口外的头像不用于检测；无法唯一判断时返回待确认，不在整页搜索预期公司名称代替头像证据。

```json
{
  "pageId": "<同一设计页 pageId>",
  "action": "hover",
  "expectedBrowser": "Edge",
  "expectedCompanyName": "示例企业",
  "frameId": 0,
  "avatarKey": "<inspect 返回的目标头像 avatarKey>"
}
```

读取器重新确认头像标识及位置，触发悬停事件，读取关联 title、aria-describedby 提示、新出现的邻近 tooltip，或已在真实页面确认的账号菜单名称元素，最后移除悬停状态。页面跳转、浏览器不匹配或头像变化时停止。只规范空白，不模糊匹配账号名称。悬停事件不能触发页面实现、提示是原生标题以外的未知弹层、证据有多个名称或页面采用无法识别的头像结构时，结果保留未知，须按真实 DOM 适配。

## 结果

| status | 含义 |
|---|---|
| identity-inspected | 返回候选与所在 frameId，未做悬停 |
| display-name-match | 选定头像的唯一名称与预期一致 |
| display-name-mismatch | 选定头像的唯一名称与预期不一致 |
| identity-unconfirmed | 没有可读名称或证据无法唯一确定 |
| identity-read-failed | 浏览器、页面、头像或读取过程不符合要求 |

返回 visibleAccountId 为同一头像账号菜单相邻位置的明确 ID 标签；未取得或不唯一时为 null，不能用会话或标签页 ID 代替。

`identityVerified:false` 表示未验证真实企业归属或前后端 ID 对应关系；显示名称匹配只完成用户认可的日常账号显示核对，不能证明主子账号归属、模板一致或配置已生效。必须另外检查模板与更新结果。证据在结果中包含读取时间、来源、原始显示文字及元素位置；不保存到公共仓库。

## 部署与验收范围

新增指令首次部署后，需要在实际使用的浏览器扩展管理页重新加载扩展卡片一次；重新连接按钮不更新已经加载的工作线程代码。后续修改单独的 frontend-identity-page.js 会在调用时重新注入，通常不需再次重载扩展。

已在真实页面通过 MCP 完成：分别识别 Chrome 后台与 Edge 设计页，定位唯一的页首头像，触发悬停，读取自定义账号菜单的企业名称，并与当次后台来源名称匹配，返回 display-name-match。实际账号菜单使用 [class*="TopBar-account-name_"]，不是通用 tooltip；只读取目标头像附近可见的该元素，不在整页搜索预期名称。已进一步在真实页面读取到同一账号菜单的可见账号 ID。该证据只证明这一页面版本的名称和可见 ID 读取，不能推广成后台归属、模板或配置版本已匹配。旧原生宿主进程启动检查在当前环境未通过；本次使用已实际接通的 HTTP 桥接，不要求为此重装宿主。
