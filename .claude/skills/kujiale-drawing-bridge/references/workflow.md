# 保存与发布

## 模板类型核验（待下次发行集成）

- 个性化配置验收前，在设计端查看施工图模板选择或切换入口，核对当前模板名称、类型、所属企业及与后台目标配置的关联；有可读 ID 时记录，无证据时标为待确认。
- 用户确认：行业模板是全球通用模板，不做个性化。不能用行业模板的出图结果判断客户企业个性化配置是否生效，也不修改行业模板来满足客户个性化需求。
- 如当前为行业模板，先定位目标企业模板，按当前测试任务切换并确认实际选中后，再执行更新配置与图纸验收。没有企业模板、同名不唯一或归属不明时，保留“待企业模板定位/选择”状态，不自动新建或修改模板归属。
- 推荐验收顺序：打开“图纸&清单” → 查看/切换并确认目标企业模板 → 后台修改并保存确认 → 设计端“设置 → 更新配置” → 必要时重新生成图纸；涉及自动标注时进入对应“编辑视图 → 自动标注” → 核验效果。
- 切换模板后重新核对客户、配置引用及前端方案，并重新更新配置和验收；不沿用切换前的截图、标注或验收结论。切换涉及额外覆盖手动编辑时，沿用任务授权范围检查。
- 模板类型核验不自动触发发布。自动检测和切换模板的执行适配器尚未实现，不能将新增流程规则报告为已自动执行。

来源：用户于 2026-11-12 补充。当前 0.5.0 发行包保持不变，本项先作为后续更新规则暂存。

## 入口、账号与目标

- 从客户账号酷家乐主页进入施工图管理；侧边栏没有入口时，从应用市场寻找。不猜测客户配置地址。
- 后端配置账号与前端测试账号同时保持登录，绑定各自的浏览器用户配置及 pageId。使用同一浏览器用户配置的两个标签页不能证明账号独立。
- 基础配置：先载入目标客户配置，核对客户、配置名称及归属，再修改。企业配置：使用用户个人后端账号，确认目标客户与配置权限。
- 记录后端 pageId、前端 pageId、客户、配置类型与名称、测试方案、模板及应用范围；真实 ID、版本等字段仅在能够读取时记录。显示名称不能代替账号 ID、配置 ID 或客户归属证据。
- 多个同名目标或归属不明时，先定位，不猜选。切换账号、客户、配置、模板或测试方案后，重新读取上下文，旧定位和旧验收证据作废。

## 修改、保存与另存为

- 修改前记录本次目标字段的原值、目标值及相关引用，逐项列出验收点。按任务需要保存最小备份或可用历史版本，不收集无关配置。
- 一轮修改完成后必须保存；保存到已确认的目标，常规保存不重复向用户索要授权。没有修改时不为完成流程而重复写入。
- 保存成功需要业务成功信息和实际回读相互印证；点击按钮、HTTP 200 或页面仍显示修改值都不能单独证明服务器已经保存。当前页面读数也不能代替持久化回读。
- 用户指定另存为时，明确新名称及客户归属，另存成功后重新获取新配置身份，并核对前端使用的是新配置。不能静默覆盖原配置，也不能把另存为当成保存或发布。
- 保存请求失败、超时或返回不明确时，先查服务器当前状态；不盲目重试，不假定失败就没有写入。保存期间又有修改时，新增修改仍视为待保存。
- 如发现其他人已修改同一配置或版本已变化，重新读取差异并处理冲突，不用旧数据覆盖新版本。当前工具不能读取版本或持久化值时，应明确该项尚无法自动核验。

## 同步、验收与失败定位

- 自动标注分支：本轮涉及自动标注设置时，后台修改并保存确认后，先在设计端“图纸&清单 → 设置 → 更新配置”等待完成，再找到目标图纸及对应视图，进入“编辑视图”点击“自动标注”，等待完成后检查标注效果。不涉及自动标注的任务不额外触发此步骤。
- 自动标注验收按本次修改检查标注对象、尺寸数值、位置及样式，记录实际结果；未重新触发自动标注时，不能仅凭原有标注判定设置已生效。再次修改自动标注配置后，重新执行保存、更新配置和自动标注。
- 自动标注如提示覆盖或清除已有手动标注，先核对本次授权范围；涉及未经授权的覆盖时不继续。自动标注自动执行工具尚未接通，不得报告已自动点击或完成。

- 前端应使用相同客户、目标配置及测试方案；有模板或部门应用关系时，核对它们实际引用的配置。没有读取证据时保留未知，不推断已正确绑定。
- 必须先确认后台保存，再在设计端“图纸&清单”的“设置 → 更新配置”执行更新，并等待完成反馈。更新前的截图不能充当本轮验收证据。
- 更新配置后，再核对或重新生成受影响图纸；本轮再次修改、保存后，必须重新更新配置和验收，不能沿用上轮结果。
- 除了本次目标字段，还检查直接受影响的图框、视图、标注或表格等相关项。仅在任务涉及打印、下载效果时，追加对应导出结果检查。
- 图纸效果没有变化时，依次排查：保存是否成功、双端客户及配置是否一致、模板/部门引用、更新配置是否完成、是否需要重新生成图纸；不自动发布，不直接扩大修改范围。
- 更新或出图过程中若出现会覆盖手动编辑、重新生成等影响的提示，先检查已有任务授权及影响范围；未获授权的额外覆盖不能默认为测试步骤。
- 只在目标修改与必要关联项均核验后报告前端验收通过；工具缺失、无权限、未登录或读取失败分别说明阻塞点。

## 发布与恢复

- 发布仅由用户明确要求触发，保存或测试请求不包含发布。已保存且此后无新增修改，才进入发布。
- 发布前核对目标客户、配置及实际生效范围；发布后检查业务结果、发布状态与可用版本信息。没有证据时不得声称已对企业、部门或全部用户生效。
- 验收失败时保留已知原值和历史版本证据；不擅自撤回发布或覆盖恢复。用户要求恢复时，按范围恢复、保存、更新前端并重新验收。

## 完成状态与交付

分开报告：目标已定位、修改已完成、保存已确认、前端配置已更新、图纸验收已通过、发布已确认。每项使用“未执行 / 处理中 / 成功 / 失败 / 结果待确认”，不能把一个状态代替另一个。

最终回复至少说明目标客户与配置、本次修改、保存结果、前端更新与出图结果；发布未被要求时标注“未发布”，并列出尚未验证项。业务字段未知时如实说明。

当前能力边界：三个只读工具可用；保存与发布只有工具入口及目标核对，执行适配器未验证；另存为、前端更新配置、生成图纸及恢复尚无自动执行工具。本文件定义应执行的流程，不证明上述操作已经实现或已经完成。

## 前端同步与出图验收

按用户确认的操作顺序执行：

1. 使用被测试账号进入设计端，在施工图纸设计界面打开“图纸&清单”。核对测试方案、客户及所用配置。
2. 后台修改目标配置后执行保存，并确认保存成功。
3. 切换到对应设计端，在“设置”中点击“更新配置”，等待更新完成；不能以后台保存成功或浏览器刷新代替此步骤。
4. 更新后再查看、生成或重新生成目标图纸，核对本次修改项，记录前端效果及证据。未完成更新配置或效果核对时，只能报告已保存、前端待验证。

“更新配置”是前端载入最新配置的独立步骤，不等于后台发布。不得为了测试自动调用发布。配置更新、保存和发布的适用范围如在实际账号中不一致，记录现象，不自行推定发布是测试前置条件。

来源：用户于 2026-11-11 补充的业务操作规则。当前尚未接通设计端“图纸&清单 → 设置 → 更新配置”的自动执行工具，不能报告该步骤已自动完成。

每轮配置修改后必须保存；确认保存成功后，才能报告配置完成。保存失败或结果不明确时，保留未保存状态，不自动重试写入，不报告完成。

`drawing_save_config(pageId, expectedConfigName)` 只保存当前目标配置，不发布、不另存为。无需因常规保存再次询问用户。

`drawing_publish_config(pageId, expectedConfigName)` 单独发布已经保存的配置。仅在用户明确要求发布时触发，不由保存工具串联调用。发布前必须核对最近一次保存成功且此后没有未保存修改；无法确认时先核对保存状态。另存为是独立操作，不能当作这两个工具的参数。

工具执行前核对 `pageId` 及目标配置名称。对账号身份、客户归属沿用双端账号规则，不能用显示名称代替客户归属证据。

当前实现状态：两个工具已注册并进行只读目标核对；真实保存、发布请求与成功回读尚未验证，返回 `adapter_not_verified`、`executed: false`，不点击按钮，不发送写入请求。此状态不能被当作已保存或已发布。下一步需要在测试配置中分别实测两条写入链路。


## 默认双端浏览器方案：Chrome + Edge

用户已选择：Chrome 登录内部账号，用于后端施工图配置；Edge 登录客户账号，用于前端施工图设计与验收。两个浏览器分别加载同一施工图桥接扩展，连接同一本机服务。任务开始通过 drawing_get_context 分别绑定两个 pageId，不能仅凭浏览器名称证明账号或客户归属。

后端使用内部账号时仍需确认目标客户及配置归属；前端确认目标企业模板，后台保存后执行“图纸&清单 → 设置 → 更新配置”，涉及自动标注时进入对应“编辑视图 → 自动标注”。实际页面连接、登录身份和配置关联尚需现场核验。

该方案作为默认使用流程暂存，不代表两个浏览器已经安装扩展或完成登录，也不触发 0.5.0 安装包更新。不同 Chrome 用户配置仍可作为备用方案。
