# 施工图配置 Agent

1. 调用 drawing_get_context，绑定后端与前端 pageId，核对客户和目标配置。客户主页无施工图入口时查应用市场。基础配置先载入客户配置；企业配置使用用户个人后端账号。显示名称不能证明账号身份或客户归属。
2. 按需调用 drawing_read_config、drawing_list_line_styles，默认最多返回 10 行。同名目标、切换账号或配置后重新定位。
3. 每轮修改完成必须独立保存，确认持久化成功；仅在用户明确要求发布时独立调用发布，不能保存后自动发布。另存为须明确名称和客户归属。
4. 前端打开“图纸&清单”；后台保存确认后，执行“设置 → 更新配置”，等待完成，再查看或重新生成目标图纸。
5. 涉及自动标注设置时，在更新配置后进入对应“编辑视图”点击“自动标注”，等待完成并检查效果。重新修改后重新保存、更新和标注；涉及额外覆盖手动标注时核对授权范围。
6. 分别报告修改、保存、前端更新、图纸验收和发布状态，不把页面可访问、本机桥接连接或点击按钮当作操作成功。


验收前先在设计端检查并确认使用目标企业模板；行业模板是全球通用模板，不做个性化。切换后重新核对配置引用，更新配置后再验图或触发自动标注。该规则待下次发行集成，当前安装包保持不变。

## 按需参考

- 执行配置任务时读取 [配置工作流](references/workflow.md)，覆盖目标绑定、并发变更、失败定位、发布和恢复。
- 查找页面或核对接口时读取 [页面与接口](references/routes.md)，只读命中的小节；观察到的请求不能当作已验证 API。

## 工具能力边界

三个只读工具已实现。drawing_save_config、drawing_publish_config 已注册，当前仅进行只读目标核对，写入适配器未验证，返回 executed:false 时不执行操作。

前端更新配置、自动标注、另存为、生成图纸和恢复尚无自动执行工具。需要这些步骤但工具不可用时，说明实际缺口并指导用户完成，不能声称已经自动执行。

浏览器扩展自动连接本机消息宿主，无需配对码。分别核验页面访问、本机桥接和 Agent 实际 MCP 调用；每个独立浏览器用户配置加载同一扩展，并分别核对账号。
