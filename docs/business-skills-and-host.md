# 业务 Skill 与 Host 接入

## 五个独立业务入口

主 Skill 保留目标判断、任务分流和共同规则；子 Skill 分别拥有 name、description、执行步骤、失败分支和完成条件，共用主 Skill 的 references。它们是同一插件的独立 Skill 入口，不是五个新服务，也不要求并行启动五个 Agent。

| 入口 | 业务范围 | 完成条件 |
|---|---|---|
| drawing-config-target | 客户载入、配置与账号定位 | 目标来源、模板、页面与证据明确 |
| drawing-line-style-workflow | 线样式新建、搜索、编辑和保存 | 按已支持分支完成字段和持久化回读；草稿转保存缺口须报告 |
| drawing-annotation-workflow | 四类注释规范识别与受支持写入 | 同 ID 回读；未适配规范字段不尝试写入 |
| drawing-object-workflow | 真分类属性、引用修改与实验还原 | 原值记录、最小变更、保存回读；再交前端验收 |
| drawing-frontend-validation | 企业模板、更新配置与实际图面 | 更新成功和当前视图效果分别有证据 |

三个 skills 目录保持镜像。项目文件已创建不等于当前聊天或个人 Skills 页已经加载；客户端需实际发现插件目录。不要把资料分组称为已经安装的 Skill。

## 什么时候提醒封装 Skill

出现多步骤业务判断、跨配置依赖、失败补偿、角色权限分支、原值还原或独立效果验收时，主动建议纳入已有业务 Skill；已有入口无法覆盖时再建立新入口。单个确定性动作保留为 MCP 工具。未支持的工具分支写进 Skill 仍然是待开发，不能靠文字流程补出执行能力。

## 失败处理和兜底

| 情况 | 处理 | 禁止自动处理 |
|---|---|---|
| Host 没发现工具 | 检查工具清单、服务配置、启动错误和是否加载当前配置 | 仅因扩展在线就宣称接入成功 |
| 目标不明或同名 | 重新读取标签、ID、浏览器和模板 | 选择搜索第一项或猜 ID |
| 原值变化、多人编辑锁 | 保存当前证据，重读差异并定位冲突 | 用旧快照覆盖或强制解锁 |
| 写入超时或部分成功 | 按原任务和 ID 读取当前状态，确认后续起点 | 更换 requestId 重放新建/保存 |
| 浏览器或服务断线 | 恢复连接后重新读文档及目标，再核对未完成任务 | 重做已确认保存；自动重装或放宽权限 |
| 页面结构改变 | 只读采集真实控件和错误，标记待适配 | 猜选择器或运行任意页面脚本补救 |
| 请求返回编码正文 | 区分收到响应与业务解析，优先现有受限页面适配 | HTTP 200 当成功、猜解密算法 |
| 前端空图或效果不符 | 检查对象存在、视图、主题、模板、更新和局部覆盖 | 自动全量生成、覆盖手动标注或随意拖入模型 |
| 用户要求还原 | 用已记录原值复用编辑工具，保存、同步并验图 | 恢复整个历史版本、删除无关内容 |

这些是流程处置规则；持久化任务恢复、跨重启幂等和通用回滚事务尚不能因此宣称已经实现。

## Host 接入怎么操作

1. 保持现有本机网关和浏览器扩展运行。扩展重载、网页刷新和 Host 工具重载是三件不同的事。
2. Codex 使用 `config.toml` 的 `[mcp_servers.construction_drawing]`；command 指向可运行的 Node，args 指向 HTTP STDIO 适配器。其他支持 STDIO 的 Host 使用 `examples/mcp-http.json`。本机 8788 网关不直接宣称兼容任意 Host 的 Streamable HTTP 配置。
3. 服务配置已存在且实际入口转发到当前网关时，不要仅因文件名仍为 client-stdio 而替换配置。检查文件内容和真实协议响应。
4. 在目标 Host 的 MCP 服务管理入口检查 construction_drawing 的连接/错误状态，使用其提供的重新连接或工具重新发现入口；不同 Host 按其实际界面操作。如果当前会话工具列表仍旧，建立新会话再核对，无需反复重载浏览器扩展。
5. 在该会话请求：“检查工具清单是否存在 drawing_get_context；存在时直接只读调用，不通过终端。”直接工具调用回执才证明该会话已暴露工具。
6. 验收分三层：STDIO initialize 正常；tools/list 有预期工具；tools/call drawing_get_context 返回实际页面。外部客户端完成这三项只证明服务可用，不能证明当前聊天已经发现它。

截至本次检查，本机 Codex 已配置施工图服务，安装目录的 client-stdio 入口实际转发至当前 HTTP 网关；当前聊天工具注册表未暴露施工图工具。因此优先检查 Host 会话加载与错误状态，不重复安装扩展、不改用户权限、不重复编辑业务配置。

## 成本、文件夹与结构化结果

主入口只分流到相关业务 Skill，详细资料按需读。通过搜索、限定 ID、分页摘要和有效缓存减少重复上下文；身份检查、完整唯一定位、保存回读及视觉验收不可省略。实际压缩率尚未测量；动态工具发现和隐藏须由 Host 支持，当前服务仍完整注册工具。

Skill 目录中的 SKILL.md 是独立入口；主/子是项目路由约定，不代表 MCP 协议的父子服务。多个 Skill 可共用一个 construction_drawing 服务和同一工具。文件夹数量不是服务数量。

网页接口就是网页调用的业务接口，不必与公开 API 相同。原始正文非 JSON 可能涉及应用编码、加密、压缩、网关或错误内容；当前编码机制未经确认，不能只凭乱码断言具体算法。可优先复用有授权会话中的已验证页面适配或现有函数；函数可访问性和参数仍须实测，不能假定总能解码。

MCP 的 JSON-RPC 信封与网站业务正文是两层。当前服务可将对象结果序列化为 text 内容中的 JSON；外层为 JSON 不代表网站原始正文已解析成功。普通摘要用于对话，结构化回执用于定位、继续任务与审计；错误、saved、published、configurationUpdated 和 effectVerified 的真实状态必须保留，未知不伪造为成功。截图以图像内容返回，不用 base64 长串填满文本。
